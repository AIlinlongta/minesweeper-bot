## 一、总体数据流与模块拓扑

### 1.1 模块拓扑（与母本 §三 一致）

```
           windowing.py ──► 窗口句柄/客户区
                 │
                 ▼
            capture.py ──► 客户区截图 (BGR ndarray)
                 │
                 ▼
           calibrate.py ──► CalibrationResult (board_origin/cell_size/rows/cols)
                 │              └── calibrate_robust（§5.3 兜底链封装，m1）
                 ▼
         grid_perception.py ──► CellClassify[]（同源模板主通道 + CNN 校验[m1.5]）
            │        │
            │        ├── template_match.py（模板匹配，perception/templates/）
            │        ├── grid_classifier.py（轻 CNN，onnxruntime，m1.5）
            │        └── 未命中 → state="unknown"（上层重采样，不硬猜）
                 │
                 ▼
             solver.py ──► SolverOutput（约束传播 + 概率兜底）
                 │
                 ▼
             state.py ──► FrameState JSON（聚合，含 action + LED 计数器对账[m3]）
                 │
                 ▼
             action.py ──► pydirectinput 点击 + 反馈回灌（真值）
                 │（点击结果回灌）
                 └────────────────────────► grid_perception / state
```

### 1.2 数据流主线（每个决策周期）

```
截图 → 自校准(首帧) → 逐格分类 → 求解 → 聚合 JSON → 动作注入 → 结果反馈(真值/状态机) → 下一周期
```

## 二、数据结构总表（JSON 契约）

> 所有跨模块传递对象均 JSON 可序列化；图像以 `numpy.ndarray` 传递（不进 JSON），此处以「类型」标注。

### 2.1 基础几何与坐标约定

- 坐标系分级：
  - **客户区坐标**（client）：相对客户区左上角，正方向右下。
  - **屏幕坐标**（screen）：`client_screen_origin + client`。
- `board_origin` 一律为**客户区坐标**下的雷区左上角。
- 格子中心点换算公式（点击用）：
  ```
  cell_center_client = board_origin + ((col + 0.5) * cell_size, (row + 0.5) * cell_size)
  cell_center_screen = client_screen_origin + cell_center_client
  ```

### 2.2 `Rect`（通用矩形）

```json
{ "x": 108, "y": 78, "w": 164, "h": 207 }
```

### 2.3 `WindowInfo`（窗口绑定，windowing 输出）

```json
{
  "hwnd": 123456,
  "pid": 8901,
  "class_name": "지뢰 찾기",
  "title": "지뢰 찾기",
  "window_rect": { "x": 100, "y": 50, "w": 180, "h": 228 },
  "client_rect": { "x": 108, "y": 80, "w": 164, "h": 207 },
  "border": { "left": 8, "top": 30, "right": 8, "bottom": 8 },
  "bind_method": "pid",
  "dpi": { "x": 96, "y": 96 }
}
```

| 字段 | 说明 |
|---|---|
| `bind_method` | 命中路径：`pid` / `class` / `title` / `size`（见 §三 windowing） |
| `client_rect` | 屏幕坐标系下的客户区矩形 |
| `border` | 由 `window_rect - client_rect` 反算的四边偏移 |

### 2.4 `CalibrationResult`（自校准输出，calibrate 输出）

```json
{
  "board_origin": { "x": 0, "y": 0 },
  "board_rect": { "x": 135, "y": 164, "w": 144, "h": 144 },
  "cell_size": 16,
  "rows": 9,
  "cols": 9,
  "difficulty": "beginner",
  "mines_total": 10,
  "confidence": 0.97,
  "method": "grid_projection",
  "anchor": {
    "face_rect": { "x": 100, "y": 90, "w": 24, "h": 24 },
    "mines_counter_rect": { "x": 10, "y": 90, "w": 40, "h": 24 },
    "timer_counter_rect": { "x": 150, "y": 90, "w": 40, "h": 24 }
  }
}
```

| 字段 | 说明 |
|---|---|
| `difficulty` | `beginner`/`intermediate`/`expert`，由 `rows×cols` 反推 |
| `mines_total` | 由难度查表（10/40/99），用于求解器与计数器校验 |
| `confidence` | 网格投影可信度（0-1），低于阈值触发锚点辅助/重试 |
| `method` | `grid_projection` / `anchor_assisted` |

### 2.5 ~~`DigitResult`~~（已移除，2026-09-09）

原 OCR（Tesseract）输出结构。OCR 主通道已由**同源模板匹配**替代（见 §3.5），数字识别结果直接体现在 `CellClassify`（§2.6）中（`source="template"`），不再有独立中间结构。模板切片与运行时渲染同源（winmine.exe 位图资源），对齐由切片边界行验证保证，无置信度阈值概念。

### 2.6 `CellClassify`（单格分类，grid_perception 输出）

```json
{
  "c": 0,
  "r": 0,
  "state": "1",
  "label_id": 1,
  "source": "template",
  "confidence": 1.0,
  "is_mine": false,
  "color": "808080"
}
```

`state` 枚举（规范化后的逻辑状态，供 solver 使用）：

| `state` | 含义 | `label_id`（CNN 12 类） |
|---|---|---|
| `"0"` | 挖开空白 | 0 |
| `"1"`..`"8"` | 挖开数字 1-8 | 1..8 |
| `"covered"` | 未挖开（灰按钮） | 9 |
| `"flag"` | 未挖开标旗 | 10 |
| `"question"` | 未挖开问号 | 12 |
| `"mine"` | 挖开地雷（触雷） | 11 |
| `"mine_red"` | 凸起红底雷（误踩瞬间） | 11 |
| `"mine_cross"` | 叉雷（错标旗位） | 11 |
| `"unknown"` | 模板未命中（confidence=0，上层重采样） | -1 |

`source` 枚举：`template`（主通道）/ `none`（unknown）/ `cnn`（m1.5 校验通道预留）。

### 2.7 `FrameState`（聚合状态，state 输出 → 落盘/回放）

```json
{
  "frame_id": 1,
  "timestamp": 1757318400.0,
  "scene": "playing",
  "game": {
    "difficulty": "beginner",
    "rows": 9,
    "cols": 9,
    "mines_total": 10,
    "mines_remaining": 10,
    "window_rect": { "x": 100, "y": 50, "w": 180, "h": 228 },
    "board_origin": { "x": 135, "y": 164 },
    "cell_size": 16
  },
  "board": [
    { "c": 0, "r": 0, "state": "1", "source": "template", "is_mine": false },
    { "c": 1, "r": 0, "state": "flag", "source": "template", "is_mine": true }
  ],
  "action": { "type": "reveal", "cell": { "c": 3, "r": 5 }, "reason": "constraint_safe" }
}
```

`scene` 枚举：`boot` / `playing` / `won` / `lost` / `paused`。

### 2.8 `SolverCell`（求解器输入格）

```json
{ "c": 0, "r": 0, "state": "covered", "digit": null }
```

- `state` 取值：`covered` / `flag` / `"0"`..`"8"`（`mine` 不进入求解，触雷即 callback 判定 `lost`）。
- `digit`：`state` 为数字时对应 0-8，其余 `null`。

### 2.9 `SolverOutput`（求解器输出）

```json
{
  "action": {
    "type": "reveal",
    "cell": { "c": 3, "r": 5 },
    "reason": "constraint_safe",
    "certainty": 1.0
  },
  "flags": [ { "c": 1, "r": 0 } ],
  "alternatives": [ { "c": 0, "r": 8, "safe_prob": 0.83 } ],
  "tie_break": false
}
```

| 字段 | 说明 |
|---|---|
| `action.type` | `reveal` / `flag` / `restart` |
| `reason` | `constraint_safe` / `prob_min` / `guess_tie` |
| `certainty` | 1.0=确定；0-1=概率兜底；`tie_break=true`=随机猜 |
| `flags` | 本周期需先落下的标旗清单 |
| `alternatives` | 概率兜底时按 `safe_prob` 降序的候选 |

### 2.10 `ActionFeedback`（点击结果回灌，真值 + 状态机）

```json
{
  "sent": true,
  "button": "left",
  "cell": { "c": 3, "r": 5 },
  "game_after": "playing",
  "cell_state_after": "1",
  "consistency_ok": true
}
```

| 字段 | 说明 |
|---|---|
| `game_after` | 注入后判定：`playing`/`won`/`lost` |
| `consistency_ok` | 感知读数与新棋盘是否满足「数字=周围雷数」自洽约束 |

### 4.2 单决策周期（主循环，m3）

```

  1. capture.grab_client(win)                      # 抓帧
  2. （若已标定且窗口未移动）复用 calib；否则 re-calibrate
  3. grid_perception.classify_board(frame, calib)  # 逐格分类（同源模板主通道 + CNN[m1.5]）
  4. state.build_frame(...)                        # 聚合 → FrameState
  5. 判定 scene：
       - lost/won → 记录并 restart（face 点击）→ 下一局
       - playing → 继续
  6. solver.solve(board, mines_total)              # 约束传播/概率兜底
  7. action.reveal/flag(c,r)                       # 注入
  8. action.get_feedback(...)                      # 反馈回灌（真值）
       - consistency_ok=False → 触发一次重感知（§五.4）
       - game_after in {won,lost} → 结算 → restart
  9. 睡眠 poll_interval（避免过频）
```

### 4.3b 鲁棒校准时序（calibrate_robust，m1 交付）

```

  2. confidence >= 0.9 → 直接返回
  3. confidence < 0.9 → detect_anchor 先验修正（anchor_assisted）→ validate
  4. 仍失败 → 重抓 ×3（间隔 poll_interval；遮挡/IME 浮窗经 bring_to_foreground 清除）
  5. 仍失败 → 脸符 restart（重开新局，covered 全盘态最易标定）→ 回到 1

### 4.4b 计数器交叉校验时序（m3）

```

## 五、重试机制与异常兜底规则

### 5.0 异常分级

| 级别 | 定义 | 处理 |
|---|---|---|
| **致命** | 环境不可用（依赖缺失、无窗口、持续黑屏、模型缺失） | 记日志 → 退出（`exit code != 0`） |
| **可恢复** | 单次找窗/截屏/识别/注入失败 | 有限重试 → 降级 → 再失败升级致命 |

### 5.1 找窗失败

1. 每 `poll_interval_s`（默认 2s）重试找窗，最多 N=5 次。
2. 仍失败 → 降级扩展匹配：类名 → 标题 → 客户区尺寸特征（详见 §三.3.2）。
3. 再失败 → 致命：报「窗口丢失/未启动」，提示用户启动 `apps/winmine.exe`。

### 5.2 截屏自检失败

1. `self_check` 非黑屏 + 尺寸合理；失败重试抓 3 次。
2. 仍失败 → 尝试 `bring_to_foreground` 后重抓 1 次。
3. 仍失败 → 致命：报「截屏失败（黑屏/窗口遮挡）」。

### 5.3 自校准失败 / 低置信度（编排归属：m1 `calibrate_robust`）

1. `confidence < 0.9` 或 `validate=False` → 走 `anchor_assisted` 路径（脸符/计数器先验）。
2. 仍失败 → 重抓帧重试校准（最多 3 次；重抓前 `bring_to_foreground` 清除遮挡/IME 浮窗）。
3. 仍失败 → 尝试 `restart` 游戏（脸符）后重新校准。
4. 仍失败 → `raise CalibrateError`；m3 主循环捕获 → 致命：报「雷区定位失败」（§5.8）。

> v1.1 职责切分：本链的**函数化封装 `calibrate_robust` 在 m1 交付**（§4.3b，脚本级独立验收）；**调用与致命退出的系统集成在 m3**（主循环一行调用 + §5.8 边界）。构件（detect_board/detect_anchor）已就位。

### 5.4 模板未命中兜底（替代原"OCR 识别兜底"）

1. 单格模板 `diff > ACCEPT_DIFF(20)` → `state="unknown"`（不硬猜）。
2. `unknown` → 上层重采样：重抓帧 + 重分类该格（瞬时渲染/抓帧噪声通常自愈）。
3. 连续 2 次 `unknown` → 触发整盘重感知；仍异常 → 走 §5.3 鲁棒校准链。
4. 原"OCR 整体识别率 < 99% → 降级模板匹配"预案已**执行完毕**（2026-09-09）：模板升级为主通道并删除 OCR。

### 5.5 ~~颜色自标定冲突~~（已移除）

颜色表随 OCR 一并废弃（同源模板无颜色查表环节）。历史上的"识别冲突"现表现为模板 `unknown`，处理见 §5.4。

### 5.6 注入失败 / 窗口自愈

1. `get_feedback` 判定「格子未变化」→ 注入未生效。
2. 处理：`bring_to_foreground` → 重试注入 1 次（同格）。
3. 仍失败 → 重跑 `find_game_window`（窗口可能移动）→ 重标定 → 重试。
4. 仍失败 → 记「窗口丢失自愈失败」→ 暂停主循环待用户干预。

### 5.7 求解器 / 游戏规则兜底

1. 约束传播无确定解 → 概率兜底取最小风险格。
2. 概率相等 → 二选一随机猜（`tie_break=true`，不计入「可解局」判定）。
3. 触雷（`scene="lost"`）→ 记录 → `restart` → 下一局（不视为 Bot 崩溃）。

### 5.8 全局异常边界

- `main.py` 主循环外层 `try/except`：捕获未预期异常 → 记录 `traceback` + 最后 `FrameState` JSON（用于回放）→ 优雅退出。
- 每个周期内异常隔离：单周期异常不终止整局，重试本周期，连续 3 次升级致命。
