# 扫雷轻量预演（minesweeper-bot）— 预演设计 v1.2

> 日期：2026-09-08 ｜ 关联文档：GOGh3-bot `docs/阶段1-分层感知架构设计-v1.md`（v1.2，本预演的架构母本）
> 定位：**GOGh3-bot 阶段1 的前置轻量预演**——验证「工程骨架 + OCR + 轻分类 + 逻辑决策」，不验证「动态视觉 + 文件解析」。
> **v1.2 变更（2026-09-08）**：① 版本事实澄清（Win10 系统不带经典 winmine.exe，经典版来自 Win7/XP；云电脑 LTSC 2019 仅支持经典 32 位 exe）；② **弃用 `xyzzy` 后门作为验证依赖** → 真值改为「游戏自身反馈 + 状态自洽约束」（后门降级为可选调试加速器）；③ 识别策略升级为**运行时自校准 + 在线自标定**（网格自动检测 / 单格自动测量 / 颜色·模板运行时采样，弃固定偏移与固定颜色表）——满足移植性要求。

## 〇、结论先行（设计要点速览）

1. **预演三层骨架对齐 GOGh3 模块命名**：`windowing` → `capture` → `grid_perception` → `solver` → `state`，做完直接映射回 GOGh3。
2. **识别策略三原则（移植性核心，v1.2 新）**：
   - **自校准定位**：雷区网格自动检测 + 单格尺寸自动测量，**不硬编码偏移/16px**；
   - **在线自标定**：颜色表、模板在**运行时采样**建立，不预置固定 RGB/固定模板；
   - **反馈式真值**：用「点击结果 + 数字=周围雷数约束 + 剩余雷计数器」做 ground truth，**不依赖 `xyzzy` 后门**。
3. **数字识别 = OCR 主通道**（对字体/渲染差异最鲁棒），颜色表退化为「OCR 读数驱动的在线自标定」仅作快速校验。
4. **验证目标 4 个**：① 通用件（window/capture/input）；② OCR 数字识别；③ 轻 CNN「合成数据→训练→ONNX→CPU 推理→评估」；④ 感知→决策→动作闭环。**不做** YOLO / h3m / 悬停。
5. ⚠️ 最大风险 = **winmine 版本/渲染差异 + Win10 DPI 缩放**——用自校准定位 + DPI 声明化解；目标对象锁定**经典 winmine.exe**。

| 挖开空白（0） | 模板（运行时采样） | 连片展开 |

### 2.4 颜色表（⚠️ 弃固定 RGB，改「在线自标定」）

- **弃预置固定 RGB 表**（不同版本数字颜色可能不同，95/98 版就改过 7/8 颜色）。
- **在线自标定**：OCR 识别出数字 N → 采该格中心像素颜色 → 建立/更新「颜色→数字」映射 → 后续格用映射快速校验 OCR 读数。版本无关、渲染无关。

### 2.5 真值来源（⚠️ 弃 xyzzy 后门，改用游戏自身反馈）

| 真值 | 机制 | 版本无关性 |
|---|---|---|
| **点击结果反馈**（主） | 求解器判「安全」→ 点击 → 游戏翻开(安全) / 爆炸(雷) | ✅ 任何扫雷版本天然具备 |
| **数字约束自洽** | 数字格 N = 周围 8 格雷数；全局一致性校验矛盾即感知出错 | ✅ 规则内禀 |
| **剩余雷计数器** | 左上角计数器 = 总雷数 − 已标旗数 | ✅ 经典 winmine 均有 |
| **首步安全特性** | 首步必安全且为 0 | ✅ 经典 winmine 均有 |

> `xyzzy` 后门（输入 `xyzzy`+Shift → 屏幕左上角像素黑/白）**降级为可选调试加速器**：仅当检测到经典 winmine 且后门可用时，用于加速调试定位；**任何验收/决策均不依赖它**。

## 四、窗口路由（windowing.py）

| 步骤 | 函数 | 要点 |
|---|---|---|
| 1. DPI 声明 | `enable_dpi_aware()` | 取句柄前必调；建议 `SetProcessDpiAwareness(PER_MONITOR_AWARE)` |
| 2. 找窗口（多路） | `find_game_window()` | **主**：类名 `FindWindow("Minesweeper", None)`；**兜底**：标题枚举「扫雷 / Minesweeper」；**扩展**：预留 UWP `ApplicationFrameWindow` 钩子（移植性） |
| 3. 取矩形 | `get_client_rect(hwnd)` | `GetWindowRect` + `GetClientRect`，算边框偏移 |
| 4. 雷区定位 | `locate_board()` | **不读固定偏移**，交给 §6.1 视觉自校准 |
| 5. 难度判定 | `detect_difficulty()` | 由网格检测出的行列数反推（9×9 / 16×16 / 30×16） |

**坐标换算（点击用）**：
```
格子 (col,row) → 屏幕：screen = board_origin + (col+0.5, row+0.5) × cell_size   # 自校准输出
```

**输入注入**：`pydirectinput` 鼠标消息；左键翻开、右键标旗、脸符重启。m0 含**真实点击回环**：感知指定格 → 注入左键 → 游戏翻开该格（此反馈即真值来源之一）。

`config/window.yaml` 草稿：
```yaml
# 实测回填（2026-09-08，XP SP3 简体中文版 winmine.exe）
class_name: "扫雷"                 # 中文版实测类名；英文原版为 "Minesweeper"
title_fallback: ["扫雷", "Minesweeper", "지뢰 찾기"]
bind_pid: null                     # bot 自启动场景直接用 Popen 的 pid 绑定（最稳）
base_difficulty: beginner          # 初级 9×9 起步
poll_interval_s: 2
capture_backend: mss
# 不配置固定 board_offset / cell_px —— 由自校准运行时输出
```

> **找窗策略（实测校准）**：① bot 自启动 → `bind_pid`（Popen 已知 pid，最稳）；② 外部已开 → 类名/标题多语言匹配（扫雷 / Minesweeper / 지뢰 찾기）；③ 终兜底 → 枚举窗口按客户区尺寸特征（初级 164×207）判定。

## 六、层① 棋盘感知（grid_perception.py）

### 6.1 自校准定位（★ 移植性核心，弃固定偏移）

```
客户区截图
  → 灰度 + 阈值二值化（按钮网格与背景分离）
  → 形态学：连成横向/纵向网格线
  → 投影法（水平/垂直直方图峰值）→ 求网格行列分割线与边界 rect
  → 锚点辅助：脸符(黄圆)正下方 = 雷区顶；计数器(左上红字区) = 雷区上方
  → 输出：board_origin(x,y) + cell_size + rows×cols（难度判定）
```
- **不依赖固定偏移/16px**；不同 exe 来源、语言、DPI 下重跑一次即可。
- 参考基准值（XP 版）仅作投影峰值的先验初值，不参与最终定位。

### 6.2 数字识别（主通道 OCR + 在线自标定校验）

| 类别 | 方法 |
|---|---|
| 数字 1-8 | **Tesseract 白名单** `--oem 3 -c tessedit_char_whitelist=0123456789` |
| 空白 0 / 未挖开 / 旗 / 雷 | 模板（运行时采样） |

**OCR 预处理（对应 GOGh3 `ocr_reader` 套路，实测调优）**：格子切片 → 放大 4-8× → 亮度阈值提字 → 可选膨胀/反色 → 多 `psm`(6/7/10) 兜底 → `isdigit()` 校验。

**在线自标定（替换固定颜色表）**：OCR 读出数字 N → 采格中心像素颜色 → 更新「颜色→数字」映射 → 后续格 OCR 结果与映射冲突则重采。版本/渲染无关。

> 降级预案（OCR 识别率 <99% 时）：数字为固定像素字体，可退「0-9 数字模板匹配」，仅作兜底。

### 6.3 轻 CNN 通道（练手，不作主判据）

| 项 | 值 |
|---|---|
| 输入 | ✅ 33×33 灰度（原格等比放大，对齐 GOGh3 口径） |
| 类别 | 12（数字 0-8 + 未挖开 + 旗 + 雷） |
| 网络 | 极浅 CNN（Conv×2 + FC），从零初始化，不用 MobileNet 骨干 |
| 训练/导出 | PyTorch CPU → ONNX → `grid_classifier.py`（onnxruntime CPU） |
| 数据 | 程序化合成（渲染各状态格子 + 增强），零人工标注 |
| 验收 | 与 OCR/颜色自标定多通道交叉验证，准确率 ≥99% |

## 七、层② 决策求解器（solver.py）

纯矩阵输入输出，脱离图像可单测（对应 GOGh3 阶段2 预演）：

| 规则 | 说明 |
|---|---|
| 约束传播 | 数字格 = 周边未挖开格雷数 → 推「必雷」「必安全」 |
| 连片展开 | 数字 0 周边自动展开（感知层同步） |
| 概率兜底 | 无确定解 → 剩余雷数 + 相邻约束算边际概率，取最小风险格 |
| 二选一 | 概率相等 → 随机猜 |
| 首步策略 | 角格或中心（首步必安全且为 0） |

## 八、输出标准化（state.py → JSON）

```json
{
  "frame_id": 1,
  "timestamp": 1757318400.0,
  "game": {"difficulty": "beginner", "rows": 9, "cols": 9, "mines": 10,
           "window_rect": {"x": 120, "y": 60, "w": 169, "h": 258},
           "board_origin": {"x": 135, "y": 164}, "cell_size": 16},
  "scene": "playing",
  "board": [
    {"c": 0, "r": 0, "state": "1", "source": "ocr", "mine": false},
    {"c": 1, "r": 0, "state": "flag", "source": "template", "mine": true}
  ],
  "action": {"type": "reveal", "cell": {"c": 3, "r": 5}}
}
```

> `board_origin` / `cell_size` 由自校准输出（非配置）；`source` 标注来源（`ocr`/`color`/`template`/`cnn`）供多通道交叉验证。

## 十一、里程碑与验收标准

| 里程碑 | 内容 | 验收标准 | 映射 GOGh3 |
|---|---|---|---|
| m0 | windowing + capture + pydirectinput + 点击回环 | 任意窗口位置下注入左键真实翻开指定格；DPI 声明生效；窗口丢失自愈；**自校准成功输出 board_origin/cell_size** | M0 |
| m1 | calibrate + OCR 数字 + 模板状态 | 网格定位像素级对齐；数字 OCR 准确率 ≥99%（**点击反馈 + 数字约束 + 计数器**三真值，非后门）；状态识别准确 | M1 + M2 |
| m1.5 | 轻 CNN 练手通道 | 合成数据→训练→ONNX→CPU 推理→评估全链跑通；≥99%；与 OCR/颜色自标定交叉验证一致 | M2 训练链预演 |
