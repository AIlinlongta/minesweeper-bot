## 二、本项目经验总结

### 感知层

1. **同源模板是免标定正解**：从游戏资源位图切出的模板与实盘渲染像素级一致（diff=0.0），OCR 全链移除后错误源归零。前提是目标程序资源可提取；无此条件时才需要 OCR/分类器双通道。
2. **切片靠结构特征，不靠均匀等分**：精灵条带用「暗行 ≥85%」定位边界；LED 条带均匀 23px 切分会得到半截字（环绕存储）。资源布局永远要目检 + 算法双验证（7 段码校验曾纠正一次映射错）。
3. **分类器必须有门控**：纯 diff 阈值会让 covered 被相邻类（question）误吸（全新盘 256 格全判 question 的实际事故），加「中心暗像素计数」门控解决。低置信不硬猜，返回 unknown 交上层重采样。
4. **采样防污染**：死亡盘雷心黑色会被误判为数字；按模板 diff 先排除雷态格，且每次点击后增量采样而非整轮结束后补采（高雷盘随机点击存活率仅 ~53%）。
5. **oracle 颜色查表注意通道序**：cv2 像素序 vs RGB 查表需 `[::-1]`，否则 1↔3、4↔5 互换。

### 校准与窗口

6. **DPI 是 RDP 环境最大坑**：200% 虚拟化 + LOGPIXELS 假报 96，游戏在 1×/2× 间随机翻转且无注册表痕迹。`AppCompatFlags\Layers = "~ HIGHDPIAWARE"` 一劳永逸，再加 cs==16 校验 + 冷重启兜底双保险。
7. **找窗必须防误绑**：精确标题匹配 + `verify_game_pid`（OpenProcess 校验进程映像）守护一切 taskkill —— 子串匹配误绑 IDE 曾导致整个会话崩溃。
8. **自愈链分层设计**：重抓 → 锚点辅助 → 前台化 → 脸符重启，逐级升级；置顶不回落（保持 TOPMOST）防其他置顶窗再遮挡；IME 浮窗主动切英文（HKL 0x04090409）+ SW_HIDE。
9. **诊断先核对产物时间戳**：调试产物生成于模板/代码修改之前时，其结论可能已失效，误导排查方向（实际发生过）。

### 决策与主循环

10. **感知矛盾 = 决策层信号**：solver 约束矛盾抛 ValueError 触发重感知，感知/决策双向闭环，比单向前馈可靠。
11. **确定性优先的三层决策**：传播确定解 → 精确枚举概率（分量超上限回退近似）→ 全局雷数守恒；猜局时 prob_min + 并列启发式（邻约束数）。
12. **异常隔离分级**：周期失败重试 → robust 校准 → 本局 error；`restarted` 单独标记防统计污染；注入失败周期内重点击自愈（瞬时丢点击不必升级）；丢窗冷重启等价重开。
13. **LED 计数器交叉对账**：`mines_total - flag数 == LED读数`，两轮自愈（重感知 → 前台化重感知）后仍败才计失败；定位算法要防棋盘红旗像素劫持聚类（先按 y 取顶部条带）。
14. **无后门验收**：真值只来自游戏胜负渲染 + 点击反馈 + 约束自洽；可解局（零猜测）100% 全解与含运气局胜率分开统计，才能区分「求解器 bug」和「运气」。

### 工程流程

15. **验收线写进脚本**：每个里程碑一个 `eval_*.py`，判定线 PASS/FAIL + exit code，重跑即回归。
16. **先合成后实盘**：纯矩阵 solver 脱离图像单测；合成盘批量验收（500 局 8 秒）通过后再上实盘。
17. **首步策略可量化**：角落首击 0 连片概率 67% > 边 51% > 中心 33%，固定角落首击消除无谓 guess_tie 计数。
18. **本机环境特有坑**：PowerShell 5 不支持 `&&`（用 `;`）；实盘脚本必须用 .venv python；**编辑会被 IDE 旧缓冲静默回写** —— 改完立即 grep 复核 + py_compile，启动长任务前最后全量验证。

## 三、GOGh3 可复用梳理

### A. 代码级直接同源（母本 §模块映射表已确认）

| 本项目模块 | GOGh3 落点 | 迁移要点 |
|---|---|---|
| `windowing.py` | `perception/windowing.py` | 整体搬运：DPI 声明、多路找窗、pid 绑定、`verify_game_pid`、TOPMOST+IME 处理、丢窗自愈 |
| `capture.py` | `perception/capture.py` | mss + 黑屏自检（`self_check`）原样复用 |
| `calibrate.py` | 对应自校准模块 | 思想迁移：不读固定偏移，运行时输出 origin/cell_size；`calibrate_robust` 分级兜底链结构照搬 |
| `state.py` / `action.py` | 同名模块 | FrameState 落盘、对账结构、pydirectinput 封装直接复用 |
| `grid_perception.py` | `grid_battle.py` + `battle_classifier.py` | 切片+分类骨架同构，模板换为 GOGh3 精灵资源 |

### B. 模式级复用（经验迁移）

- **「同源模板主通道 + 轻分类器交叉验证」管线**：m1.5 的 合成增广 → 训练 → ONNX → 与主通道对账 全流程可复制到 GOGh3 的 13 类轻 CNN（grid_battle 场景更复杂，交叉验证兜底更有价值）。
- **感知↔决策双向闭环**：solver 矛盾触发重感知的接缝设计，直接对应 GOGh3 阶段1→阶段2 的接口契约。
- **反馈式真值 + 无后门验收**：点击回环做真值源；里程碑判定线脚本化（exit code）。
- **分级异常隔离主循环骨架**：§5.8 的重试/升级/restarted 语义可整体移植。
- **对账思想**：外部状态（LED 计数器）与内部状态（旗数）周期性对账 + 两轮自愈，适用于 GOGh3 任何有外部可观测状态的场景。

### C. 明确不外推的边界（母本边界声明）

- 本预演通过 = **骨架验证通过**，不等于 GOGh3 视觉难点通过 —— **动态视觉 + 文件解析**是预演明确不覆盖的，仍是 GOGh3 阶段 1 的主战场。
- OCR 在本项目已弃用，但 GOGh3 若无同源资源，仍需 OCR/分类双通道（不可照搬「移除 OCR」结论）。
- 概率求解器（`solver.py`）是扫雷特化实现，GOGh3 阶段 2 决策层只复用「确定性优先 + 概率兜底 + 矛盾即信号」的编排思想。
